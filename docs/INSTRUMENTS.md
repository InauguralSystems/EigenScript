# Instrument register

This register records devices whose output can decide a merge, a project ruling, or a published figure. For deterministic pass/fail gates, “resolution” is detection power: the count and classes of faults demonstrated by plants. “No plants” means that no fault injection is registered; it is not a claim that the gate is ineffective. For quantitative instruments, “UNMEASURED” still means the tree has no numeric A/A floor plus a known-size planted effect. “Validated” means comparison with the named external or reference baseline, not merely a checker self-test.

## Derivation and merge rule

The population is obtained by the enumeration commands below rather than a hand-maintained list. A row is merged only when several callers invoke the same device with the same question: the CI callers remain named in the device or population cell. Distinct workflow jobs remain distinct rows because their runner, build, or required-check verdict differs.

Plant counts are derived, never maintained as a second list. A self-test's declared cases include positive controls as well as planted faults, so `plants: N` is an UPPER BOUND on the fault classes a device has been shown to catch, not a count of them. For each static-checker row, run the registered command that actually exercises that detector: derive it with `awk -F ' \| ' 'NF > 1 { print $2 " -> " $3 }' tools/selftests.txt` and use the command only when that row's trigger field names the detector (or run the detector's own `--selftest`). Do not transfer coverage from `tools/precheck.sh --selftest`: that command exercises a temporary stub and only measures the precheck classifier. Run `python3 tools/observer_oracle/plants.py --selftest` for the oracle plant; and run `git grep -l -i plant -- tests/sections | sort` to enumerate the suite plant rows, then count each row’s explicit planted cases. A command's named PASS/RED lines are the class inventory. CI-job totals are the union of plants in commands that job invokes; `python3 -c "import yaml; print(yaml.safe_load(open('.github/workflows/ci.yml'))['jobs'])"` derives the job population and the workflow `run:` blocks establish those callers.

Audit table shape with `awk -F '|' 'BEGIN{s=0} /^## Observer and benchmark devices/{s=1} /^## Merge-deciding gates/{s=0} /^\|/{want=s?11:10; if (NF!=want) {print NR ": " NF " fields, expected " want; bad=1}} END{exit bad}' docs/INSTRUMENTS.md`. Audit the quantitative separation with `awk -F '|' 'BEGIN{s=0} /^## Observer and benchmark devices/{s=1; next} /^## Merge-deciding gates/{s=0} s && /^\| `/ {if ($6 !~ /UNMEASURED/ && $6 !~ /A\/A.*plant/) {print "quantitative resolution is neither UNMEASURED nor a measured A/A floor plus a plant: " $2; bad=1} if ($7 !~ /(plants:|no plants)/) {print "missing plant coverage: " $2; bad=1}} END{exit bad}' docs/INSTRUMENTS.md`.

These are not claims that a device is useless; they identify decisions whose cutoff is finer or broader than a resolution the tree has actually established.

1. **Observer oracle raw-accuracy headline.** `score.py` prints accuracy over its corpus, while its own header says the reference is correlated because it shares the observer window and tolerances. No A/A floor plus known-size boundary plant establishes an accuracy resolution; the aggregate can also hide a predicate below a constant-answer baseline (issue #1993).
2. **Two-build cost gates (#1939).** the historical phase-2 cost script is absent on this branch, but the historical declarations remain consumed by `bench/check_regression.sh` in the issue’s two-build comparison. #1939 records about a 3% base-`Ir` build difference and a 0.33 percentage-point delta disagreement against a 0.2-point declaration margin. That decision is finer than any registered A/A resolution.
3. **JIT fleet bench (#1178).** It rules on paired medians and floors without a differential against hyperfine or `perf stat`, and has no A/A resolution measurement.
4. **Quantitative register rows marked UNMEASURED.** Their thresholds have no tree-demonstrated numeric A/A floor plus known-size planted effect; deterministic gates instead report plant coverage above.

## Reading the register

For a deterministic checker, plant coverage is its recorded detection power, not a statistical noise floor. For a quantitative instrument, catching a large plant proves that it can fire but does not establish the smallest reliably separable effect. “Validated against baseline” still requires the same population to be measured by both devices.
