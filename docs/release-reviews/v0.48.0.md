## Part C: the delta a28c539f..0d1ded77, and dead code over every build profile

I started from `main` at exact SHA `0d1ded77c82b894ceaf12548691fdce10e4db1bb`. This part reviews the three-commit delta after parts A/B and completes part B's dead-code build cross-check over `v0.47.0..0d1ded77`. PR #2130 had not landed at that SHA and is therefore outside the delta.

### Delta review

The delta is three commits: #2126 routes recoverable UBSan diagnostics through the fuzz-smoke classifier, #2121 gives every `jit_diff` arm the same `EIGS_SEED_RANDOM` and removes #2123's waiver, and #2131 adds the deterministic compiler-environment-count TSan control.

- **Docs drift.** `EIGS_SEED_RANDOM` is listed with `seed_random` in `docs/BUILTINS.md`. The candidate documented integer parsing, exit 2, the CLI/embed distinction, and trace/replay interaction, but did not say that empty means unset. This PR makes all three requested boundary claims explicit: CLI-only, malformed nonempty values exit 2, and empty/unset values do nothing.
- **Stale references.** The waiver case and its comment are gone from `tools/jit_diff.sh`. The superseded `changes/internal/2120-waive-random.md` still described the seed as pending even though #2121 had landed; this PR rewrites it in the past tense. The replacement fragment records that the waiver was replaced.
- **Config drift.** The changed `tools/selftests.txt` row names both fixtures it runs and selects the new aggregate mode. The added suite fragment invokes the added seed test. The changed CI fuzz-smoke plant invokes an existing `fuzz/run_fuzz.sh` mode. Workflow, tier, enrolment, CodSpeed, and self-test-list checks found no dangling row.
- **Duplicated logic.** The fuzz smoke's ASan, LSan, and UBSan paths share its existing sanitizer classifier. The four differential arms share one seed policy in `tools/jit_diff.sh`; no second parser for the CLI variable was added. The TSan control reuses the runtime environment accessors it is designed to exercise.
- **Dead code.** The delta adds `eigs_seed_random`, `builtin_seed_random`, and the three TSan control functions. The builtin registry calls `builtin_seed_random`; both the builtin and CLI call `eigs_seed_random`; `main` dispatches the TSan control, which starts its reader and writer. All remain present in the extension-complete binary or have direct source callers.
- **Fragments.** Each user-visible or internal delta change has a fragment. The obsolete waiver fragment was rewritten as completed history rather than shipping a claim contradicted by the replacement fragment.

### Completed dead-code cross-check

The population was derived, not hand-written, with a zero-context diff over `v0.47.0..0d1ded77`: 116 added C function-definition candidates in `src/`. Whole-tree exact-name reference counts found no candidate with fewer than two `src/` occurrences (definition plus caller/declaration/registry). `nm -A` was then compared across the release, server, server-db, and zlib executables; local static functions that do not survive as named optimized symbols were checked by the source caller scan and `-Wunused-function` compilation.

The built profiles were:

- `make`: hosted release, including gfx;
- `make server`: HTTP, net, model, and gfx;
- `make server-db`: the server set plus db;
- `make zlib`: the separately gated zlib extension;
- `make gfx`: confirmed as the documented alias of the hosted release build.

Thus every extension profile enumerated by the Makefile was covered; `http`, `net`, and `full` are compatibility aliases of `server`/`server-db`, not distinct binaries. A clean `server-db` rebuild with `-Wunused-function` compiled every runtime and extension translation unit and emitted no unused-function warning. Every one of the 116 added candidates has either a binary symbol/cross-reference or a source caller, so there is no dead-code finding.
