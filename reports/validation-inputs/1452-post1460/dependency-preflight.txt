Dependency preflight is a mandatory phase BEFORE the first build or full suite. Use this same exported environment for every subsequent gate and both reference/candidate builds. All output and exact exits go into a new validation-1452-r3/logs directory. Keep every setup failure; do not overwrite earlier attempts.

1. Record uname -a, uname -m, bash --version, id -u, command -v python3/gcc/make/git/objdump/timeout/valgrind, python3 executable/version, compiler version, and /usr/bin/time --version. Do not dump the full environment or credentials. Native entry/OSR coverage requires Linux x86_64 with executable mmap; a fallback JIT pass does not meet the native bar.
2. Required packages for this lane: build-essential (gcc/make/binutils), git, ca-certificates, python3, python3-yaml, valgrind (Cachegrind), time (GNU /usr/bin/time). These are the relevant union of .devcontainer/Dockerfile, CONTRIBUTING.md, ci.yml and bench/check_regression.sh. clang/libpq-dev/zlib1g-dev/postgresql-client/gdb/curl are declared in the full dev image but are not required to build these release/asan variants. Do not mistake the top-level runtime Dockerfile for the dev/test image.
3. Probe the ACTUAL python3 used by shell children: python3 -c 'import sys, yaml; print(sys.executable); print(yaml.__version__); print(yaml.__file__)'. An unrelated Python interpreter having yaml is insufficient.
4. If required tools/imports are missing, explicitly provision them before any heavy gate. On Debian/Ubuntu, use apt-get directly as uid 0, or sudo -n apt-get if available. Try a bounded install from the existing index, then refresh and retry once (timeout 180 apt-get install -y --no-install-recommends build-essential git ca-certificates python3 python3-yaml valgrind time; if that fails, timeout 120 apt-get update followed by the bounded install). Capture both attempts separately. Never request escalation or wait for an interactive sudo password. Package-manager success must be followed by actual import/tool probes.
5. If the gate's python3 still cannot import yaml (for example /usr/local python3 shadows distro Python), use a task-owned venv OUTSIDE the source tree: python3 -m venv <artifact-root>/dependency-venv, then <venv>/bin/python -m pip install --require-hashes -r .github/requirements-release.txt, and export PATH=<absolute-venv>/bin:$PATH. The frozen repository lock declares PyYAML==6.0.3 with hashes. If venv is unavailable, install python3-venv using the same bounded noninteractive package route and retry creation once; if /usr/local python3 still lacks venv support, explicitly use /usr/bin/python3 -m venv when that distro interpreter is available, then export that venv PATH and verify the shell child python3 again. If pip is unavailable inside a successfully created venv, use python -m ensurepip there. Do not alter the requirements or use a different unverified requirements file. Preserve failures and final package/version receipt. Do not modify tracked source or global interpreter aliases.
6. Re-run python3 import probe after PATH export, then run bash tools/workflow_yaml_check.sh on the actual pinned candidate. Require exit 0 and exactly one final workflow-yaml: OK (examined=N file(s), loader=pyyaml) with N>0; independently inventory .github/workflows/*.yml and *.yaml and compare N. A YAML content error is a real gate failure; only the missing-import setup failure is eligible for dependency repair.
7. Verify valgrind --version, valgrind --tool=cachegrind --help, and /usr/bin/time -f '%M' true. Verify gcc, make and objdump execute. A missing/unusable Cachegrind or GNU time must be corrected now; do not discover it after the sanitizer suite. An instrument probe is not a workload pass.
8. Inventory optional coverage: bash <=3 via tools/portability_parse_check.sh; Vim and TextMate modules via tests/test_editor_grammars.sh declarations. They may retain explicit platform/dependency SKIPs allowed by the unchanged acceptance bar. Record reasons; do not present these as passes. Extension-disabled release/asan sections are named variant skips, not missing-dependency excuses. No new extension matrix is required by this retry.

Only after steps 1-7 actually pass may release-suite validation start. If required setup cannot be provisioned by these bounded routes, report BLOCKED-SETUP with exact command, exit, stderr and unresolved probe. Do not launch a heavy job with known missing prerequisites. Source coordinate divergence always stops immediately.
