- `range` now raises a `value` error when a bound or step is outside the int range. Before, `range of [0, 3e9]` silently returned an empty list. The same happened to in-range bounds whose span overflowed (`range of [-2e9, 2e9]`), which now reports the 1M-element limit error. The bitwise operators (`& | ^ << >> ~`) and the `bit_*` builtins no longer perform an undefined float-to-int cast on operands outside int64, and a left shift of a negative value is now defined (two's-complement). Such an operand now behaves as INT64_MIN, which is what x86 already produced and what the JIT computes, so results are unchanged on x86 and every execution tier agrees. Calls into JIT-emitted code skip clang's `-fsanitize=function` probe, which crashed sanitizer builds when emitted code began at the start of a page. Found by libFuzzer.
